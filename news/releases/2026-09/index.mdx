We are pleased to announce the September 2026 release of openRuyi.

The release strengthens security maintenance, advances RISC-V and RVA23 integration, refreshes the kernel and graphical stacks, and expands cloud, storage, and developer tooling.

{/* truncate */}

## Highlights

* **Security-focused package refresh**: We updated `expat` from `2.8.1` to `2.8.4`, `bubblewrap` from `0.11.2` to `0.12.0`, and `libheif` from `1.21.2` to `1.23.4` with confirmed upstream vulnerability fixes. Additional security updates cover container runtimes, image-processing libraries, and Python tooling; the verified CVE and GHSA details appear in the Security Updates section below.

* **RISC-V and RVA23 code generation**: OpenJDK gains missing RVA23 `zbs` and `zfa` instruction support together with RISC-V backend optimizations for CRC32/C, DES, vector-state handling, and address rematerialization. GCC 16 receives backported fixes for BCLR-related wrong-code generation on RV64, while DPDK enables RVA23 vector paths and can load compressed firmware through libarchive.

* **Kernel and core platform integration**: We updated the mainline kernel from `7.2.0` to `7.2.6` and the LTS kernel from `6.18.46` to `6.18.52`. The default container seccomp profile now permits `riscv_hwprobe` for RISC-V workloads.

* **Desktop and graphical stack improvements**: KDE Frameworks advances from the `6.28` series to `6.29`, and KDE Gear applications move from `26.04.2` to `26.08.1`; Mesa advances from `26.1.1` to `26.2.2`. Mesa also enables the NVK driver, and the Vulkan SDK stack moves to `1.4.357.0`, improving the graphics base for desktop and headless workloads.

* **Cloud, storage, and container capabilities**: openRuyi adds the Cloudpods `4.0.3` stack and expands the distribution-managed dependency closure for MinIO and KES, including etcd-backed and notification integrations. Ceph packaging now creates its service user through `systemd-sysusers` and supplies missing manager dependencies, while SPDK enables its io_uring, RBD, and SMA modules.

* **Toolchain and packaging reliability**: We updated Go from `1.26.5` to `1.27.1` and refreshed a broad set of Go modules and build checks for Go 1.27 compatibility.

## Security Updates

* `bubblewrap` was updated from `0.11.2` to `0.12.0`, fixing [CVE-2026-87766] ([GHSA-pxhw-h44j-8pfx]).

* `python-virtualenv` was updated from `20.35.4` to `21.7.4`, fixing [CVE-2026-22702] ([GHSA-597g-3phw-6986]).

* `python-mcp` was updated from `1.26.0` to `2.0.0`, fixing [CVE-2026-52870] ([GHSA-hvrp-rf83-w775]) and [CVE-2026-52869] ([GHSA-jpw9-pfvf-9f58]).

* `expat` was updated from `2.8.1` to `2.8.4`, fixing [CVE-2026-66046], [CVE-2026-76641], [CVE-2026-76956], and [CVE-2026-76957].

* `libheif` was updated from `1.21.2` to `1.23.4`, incorporating fixes for [CVE-2026-62289], [CVE-2026-62291], [CVE-2026-62292], [CVE-2026-62377], [CVE-2026-84383], [CVE-2026-84384], [CVE-2026-84444], [CVE-2026-84446], [CVE-2026-84447], [CVE-2026-84448], [CVE-2026-84450], and [CVE-2026-84451]. The update also addresses [GHSA-2jg2-4ch7-h545], [GHSA-46rp-pcq2-rpmr], [GHSA-x8r2-mggj-j6wr], [GHSA-8fmq-r4pf-7m57], [GHSA-w7mc-p8jc-p853], [GHSA-4jqm-2x34-6f6r], [GHSA-4h82-g446-83fm], [GHSA-9rj8-5mp5-26c9], [GHSA-mw6f-29j3-76f4], [GHSA-8857-r8x5-7499], [GHSA-vg7w-rp49-4fc2], [GHSA-xrp2-63fq-jm8q], [GHSA-prgh-72vc-3xmc], [GHSA-fqpw-fj22-78w4], [GHSA-4rv4-953r-p24q], and [GHSA-rhgw-q5g8-xjh2]. CVE IDs not verified for these GHSA-only fixes.

* `crun` was updated from `1.27.1` to `1.28`, fixing [CVE-2026-47766].

* `imagemagick` was updated from `7.1.2.25` to `7.1.2.31`, fixing [CVE-2026-93586] ([GHSA-3rjr-534c-8v67]), [CVE-2026-93589] ([GHSA-4gg2-hfgh-6f5c]), [CVE-2026-93590] ([GHSA-7hjx-392p-f8cm]), [CVE-2026-93587] ([GHSA-89wq-f8f6-2j2v]), and [CVE-2026-93588] ([GHSA-92rw-c5mw-27v4]).

* `python-ujson` was updated from `5.13.0` to `6.0.0`, addressing [GHSA-8g3h-c45c-7pg3]. CVE IDs not verified.

* `python-datasets` was updated from `4.8.5` to `5.0.1`, fixing [CVE-2026-66007].

* `python-pytorch-lightning` was updated from `2.6.4` to `2.6.6`, fixing [CVE-2026-58659].

We continue to provide four editions for different scenarios: **Server**, **Container**, **Desktop**, and **Zero (BSP validation)**. You can download openRuyi from the [openRuyi release site](https://releases.openruyi.cn/).

Existing users can upgrade by running `dnf update`.
